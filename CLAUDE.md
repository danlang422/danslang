# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Daniel Lang's personal site (danslang.com) — a home page, portfolio, and devblog, entirely generated by Eleventy from `content/`.

## Commands

- `npm run build` — runs `eleventy`, builds `content/` into `_site/`
- `npm run start` — runs `eleventy --serve`, builds and serves the whole site with live reload

There is no test suite, linter, or type checker in this repo.

## Architecture

The whole site is Eleventy-rendered from `content/` — home, portfolio, and posts all share one layout (`base.njk`) and one build output (`_site/`). There is no separate hand-written static-HTML half; every page controls its own URL via an explicit `permalink` in front matter, decoupled from `dir.output`'s name.

### Eleventy config (`.eleventy.js`)

- Input dir: `content/`
- Output dir: `_site/`
- Includes dir: `content/_includes/`
- Passthrough copies: `assets/`, `styles.css`, `script.js` (these live at the repo root as source but get copied into `_site/` on build — they're not processed by Eleventy, just carried through)
- Custom shortcodes: `{% shot src, alt, crop %}` (single image, `crop` adds the crop/expand treatment used by the lightbox) and `{% figrow "caption" %}...{% endfigrow %}` (paired shortcode, lays multiple `{% shot %}` calls side-by-side under one shared caption). Both are usable directly inside `.md` post content since `markdownTemplateEngine: "njk"` is set.

### Content structure and permalinks

- `content/home.njk` → `permalink: /` — the site's homepage (hero/about/CTA). Not a post listing.
- `content/portfolio.njk` → `permalink: /portfolio/` — the project grid.
- `content/index.njk` → `permalink: /posts/` — the "all posts" listing page. Iterates `collections.posts`.
- `content/devblog.njk` → `permalink: /posts/devblog/` — a filtered listing. Iterates `collections.devblog`.
- `content/posts/*.md` — individual posts. Front matter `tags` determines collection membership (e.g. `tags: [posts, devblog]` or `tags: [posts, case-study]`); a post only shows up on the devblog listing if it's tagged `devblog`. Optional `wide: true` widens the post column (see `post.njk`).
- `content/posts/posts.json` — Eleventy directory data file applied to every file in `content/posts/`: sets `layout: post.njk` and `permalink: /posts/{{ page.fileSlug }}/`.
- `content/_includes/base.njk` — the shared HTML shell (head, nav, **footer**) for every page on the site, including home and portfolio. `<title>` uses `{{ title }} — Daniel Lang` by default; set front matter `titleOverride` to bypass that pattern entirely (used by home/portfolio to keep their own exact title text). Nav active-state is computed from `page.url`, not hardcoded.
- `content/_includes/post.njk` — wraps post content in `.post-body` (or `.post-body--wide` when `wide: true`), adds title/date, and the lightbox `<dialog>`.

`_site/` (the build output) is gitignored — Cloudflare rebuilds it fresh on deploy. Don't hand-edit anything under `_site/`; edit the corresponding source under `content/` (or the passthrough-copied root files) and rebuild.

### Styling and scripting

- `styles.css` is one global stylesheet for the entire site, organized with section comments (`/* NAV */`, `/* HERO */`, `/* PORTFOLIO */`, `/* BLOG POST */`, `/* LIGHTBOX */`, etc.) — check for an existing section before adding new rules.
- `script.js` is one global script covering unrelated small behaviors: footer year, the homepage glasses hover/click speech bubble, and the post-image lightbox (click an image in `.post-body` to open it in a `<dialog>`). Lightbox listeners are only meaningful on post pages; the glasses/speech-bubble listeners are only meaningful on the homepage. Both are guarded with existence checks so the single script can be safely included everywhere.

## Deployment

Deployed to Cloudflare (`wrangler.jsonc`), serving Eleventy's build output as static assets (`assets.directory: "_site"`). Cloudflare runs the Eleventy build (`npm run build`) as part of the deploy, per the comment in `.gitignore`.
